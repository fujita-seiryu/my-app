# 移動ドピッチトレーナー 開発設計書 (v7)

## 1. 背景・目的

- 御詠歌を行っており、**移動ド**（相対音感）の考え方には慣れている
- 一方で**楽器演奏の経験がなく、コード（和音記号）を見ても理解できない**
- Roland VT-12（ボーカル・トレーナー）の実機を所有・使用しているが、練習曲・録音再生などの機能は不要
- VT-12使用時は、自作の**円形シール**（ド/レ/ミ/ミ#/ファ/ソ/ラ/ラ#/シの階名を記載）を本体の上に貼り、基準音が変わるたびに貼り替えて使っていた
- **これをデジタルで再現したい**：基準音を選ぶだけでシールの貼り替えなしに同じ表示が得られるようにする
- メトロノームも欲しい（拍子の強弱区別あり）
- **設計の根本方針**：本アプリはVT-12という音楽専門メーカー（Roland）が実売した専用ツールへのリスペクトを出発点として作り始めた。円形メーターの配置は、数学的な正確さ（半音距離の比例配置）よりも、**実機シールに忠実であること**を優先する

## 2. 想定ユーザー・利用環境

- 開発者本人（1名）。楽器演奏・五線譜の知識なし、移動ド唱法には慣れている
- **スマホのブラウザ**で使用（VT-12のような縦型・手持ちサイズのUI）
- VT-12実機と見比べながら開発・調整する

## 3. 必須機能（スコープ内）

| # | 機能 | 内容 |
|---|------|------|
| 1 | 基準音（音名）選択 | イロハニホヘトの自然音＋#（例：ヘ#）＝計12種類から選択 |
| 2 | 調（長調/短調）選択 | 音名とオクターブ層セレクタの間に配置。短調では「ミ」「ラ」の鳴る周波数がそれぞれレ#相当・ソ#相当に切り替わる |
| 3 | オクターブ層選択 | 基準／ー1／ー2 の3段階（4段目の「＋」は実使用がないため廃止） |
| 4 | マイク入力によるリアルタイムピッチ検出 | ブラウザのマイク入力から歌声の基本周波数(f0)を検出 |
| 5 | 移動ド変換・表示 | 検出した音を、選択した基準音からの相対位置に変換し、実機VT-12のシール配置を再現した9分割の円形メーターで表示 |
| 6 | 音程のズレ表示 | ジャストな音程からのズレ（セント単位）を円形メーターの光り方・色で表現 |
| 7 | メトロノーム | BPM設定、開始/停止、拍子（4拍子など）に応じた強拍・弱拍の区別 |

## 4. スコープ外（あえて実装しない機能）

- 内蔵練習曲・トレーニングコンテンツ
- 録音・再生・レビュー機能
- 2声同時検出（コーラス機能）
- 教則本連携・ウォームアップモード

## 5. 基準音・調・オクターブ層の選択UI（3軸分離方式）

以前は「基準音×オクターブ」を1つの選択肢（例：ーーハ、ーハ、ハ、＋ハ…）としてまとめて考えていたが、7音×#の有無×オクターブ段階＝最大42通りとなり選びにくいため、**独立した選択UI**に分離する。音名とオクターブ層の間に、調（長調/短調）の選択を追加した。

### 5-1. 基準音（音名）選択：12種類
```
イ・イ#・ロ・ハ・ハ#・ニ・ニ#・ホ・ヘ・ヘ#・ト・ト#
```
（ホ-ヘ間、ロ-ハ間はもともと半音のため「ホ#」「ロ#」は存在しない＝ピアノの黒鍵5つに対応する数と一致）

### 5-2. 調（長調/短調）選択：2種類
音名セレクタとオクターブ層セレクタの間に配置。詳細は6-2参照。

### 5-3. オクターブ層選択：3段階
| 表記 | 意味 | 目安 |
|------|------|------|
| 基準 | 御詠歌の楽譜上の基準（記譜音） | 女性キーよりやや高め寄り |
| ー1 | 基準より1オクターブ下 | おおむね女性キー相当 |
| ー2 | 基準より2オクターブ下 | おおむね男性キー相当 |

「＋」（基準より1オクターブ上）は実際の声域で使用しないため廃止。

### 5-4. 補足：男女ワンタッチ切り替え（検討中の追加案）
昔使っていた「コンダクター」という機械にあった、ボタン一つで基準音を1オクターブ下げて男性キー用に切り替える機能を、ショートカットボタンとして実装することも検討。実装が固まった段階で正式に採用可否を決める。

## 6. 円形メーター表示ロジック（実際のシールを再現）

### 6-1. 表示する9区画（実機同様12区画の枠に配置、固定・唯一の表示パターン）
実機VT-12は12個の固定ピッチ位置（半音ごと）を持つため、円形メーターも**12区画（30°ずつ）を土台**とし、そのうち9区画にラベルを配置する。残り3区画（実際に使わない半音の位置）は空白のまま残す。

```
反時計回り（上行方向）: ド → レ → ミ → ミ# → ファ → ソ → ラ → ラ# → シ → (ド)
```
円周上の配置（画像から再現、時計回り）：
```
ファ → (空白) → ソ → ラ# → ラ → (空白) → シ → ド → (空白) → レ → ミ# → ミ → (12時に戻る)
```
- 12時の位置：ミ（左）／ファ（右）が隣接
- 空白マスは**ド-レ間・ファ-ソ間・ラ-シ間**の3箇所（実機で使わない半音に相当）

### 6-2. 長調・短調の切り替え（実機コンダクターで周波数確認済み）
実際に御詠歌で使っているコンダクター実機で周波数を確認した結果、**短調では「ミ」がレ#相当、「ラ」がソ#相当の周波数**になることが判明した。

- 階名ラベル（移動ドの呼び方）自体は長調・短調で変わらない。「ミ」「ラ」という表示のまま、実際に鳴る／マッチング判定する周波数だけが切り替わる
- それ以外の7区画（ド・レ・ファ・ソ・シ・ミ#・ラ#）は長調・短調で変化しない
- 半音値の対応：

| 階名 | 長調のsemitone | 短調のsemitone |
|------|------|------|
| ミ | 4 | 3（レ#相当） |
| ラ | 9 | 8（ソ#相当） |

- 調セレクタ（5-2）で切り替えると、リング上のミ・ラの位置表示はそのままに、ピッチ判定とタップ再生の周波数だけが即座に切り替わる

### 6-3. ミ#とファの扱い
**ミ#とファは異名同音（同じ周波数）**のため、実際に検出されるピッチは9区画中8種類のみ。ミ〜ファの間の音が検出された場合、「ミ#」区画と「ファ」区画の**両方を同時にハイライト**する。それ以外の7区画は該当する検出音があればその区画のみ単独でハイライトする。

### 6-4. オクターブ違いの表示（実機検証で判明）
選択した基準音・オクターブ層から算出した「基準オクターブ」に対して、実際に検出された音が別のオクターブだった場合でも、移動ドの度数（階名）としては正しく同じ階名で表示されるべき。ただし、どのオクターブで鳴っているかが分かるよう、色を変えて区別する：

| 状態 | 表示色（例） |
|------|------|
| 基準オクターブと一致 | 赤 |
| 基準オクターブより下 | 黄 |
| 基準オクターブより上 | 青（実使用は少ない想定） |

計算式：検出周波数からセント差を算出し、最も近い階名区画を求める。オクターブ差は `round(12 × log2(検出Hz ÷ 基準ドHz) / 12)` 等で算出し、表示色に反映する。

## 7. 音域

- ピッチ検出自体は基準オクターブの前後1オクターブ程度（計3オクターブ弱）をカバーできるようにし、6-4のオクターブ判定ロジックで正しく色分けする
- 範囲外の周波数（ノイズ・倍音誤検出）は無視する

## 8. デザイン方針（VT-12シール踏襲・スマホ縦型）

```
┌───────────────────┐
│ 音名:[ハ▼] 調:[長調▼] オクターブ:[基準▼] │
│                             │
│        ミ  │  ファ           │
│     ミ#     (空白)   ソ       │  ← 実機同様12区画の枠
│    レ    ╭────╮   ラ#        │     （9区画にラベル、3区画は空白）
│  (空白)    │現在│   (空白)     │
│    ド    ╰────╯   ラ         │
│        シ                   │
│                             │
├───────────────────┤
│ ♪ BPM[ 92 ] 拍子[4/4▼]      │
│      [ ● 強拍 ○ ○ ○ ]       │
│      [ 開始 / 停止 ]         │
└───────────────────┘
```
- 縦長（スマホ画面向き）の1画面完結レイアウト
- 音名・調（長調/短調）・オクターブ層は横並びの3つの独立したセレクタ
- 円周は実機同様12区画（30°ずつ）を土台とし、9区画にラベルを配置。残り3区画（ド-レ間・ファ-ソ間・ラ-シ間）は空白
- 現在検出中の音の区画を光らせる。オクターブ差は色で表現（6-4参照）

## 9. 技術方針

- **形態**：ブラウザで動く単一Webアプリ（index.html / style.css / script.js）、サーバー不要
- **マイク入力**：`getUserMedia`
- **ピッチ検出**：Web Audio API の `AnalyserNode` ＋自己相関法（autocorrelation）
- **メトロノーム**：`AudioContext.currentTime` 基準の lookahead スケジューリング。拍子情報を保持し1拍目にアクセント音
- **フレームワーク**：Vanilla JSで十分
- **スマホ対応**：viewportメタタグ、タッチ操作前提のUIサイズ、ポートレート固定推奨

## 10. 音名対応（イロハ ⇔ 移動ド 変換ロジック）

```
イ = A (ラ)　ロ = B (シ)　ハ = C (ド)　ニ = D (レ)
ホ = E (ミ)　ヘ = F (ファ)　ト = G (ソ)
```
選んだ音名を「ド」として、検出周波数との半音差から、6章の円形メーターの区画を点灯させる。オクターブ層（基準/ー1/ー2）は、その「ド」の絶対的な高さ（何Hzか）を決定する役割。
