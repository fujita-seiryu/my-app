# 移動ドピッチトレーナー 開発設計書 (v16)

## 1. 背景・目的

- 御詠歌を行っており、**移動ド**（相対音感）の考え方には慣れている
- 一方で**楽器演奏の経験がなく、コード（和音記号）を見ても理解できない**
- Roland VT-12（ボーカル・トレーナー）の実機を所有・使用しているが、練習曲・録音再生などの機能は不要
- VT-12使用時は、自作の**円形シール**（ド/レ/ミ/ミ#/ファ/ソ/ラ/ラ#/シの階名を記載）を本体の上に貼り、基準音が変わるたびに貼り替えて使っていた
- **これをデジタルで再現したい**：基準音を選ぶだけでシールの貼り替えなしに同じ表示が得られるようにする
- メトロノームも欲しい（拍子の強弱区別あり）
- **設計の根本方針**：本アプリはVT-12という音楽専門メーカー（Roland）が実売した専用ツールへのリスペクトを出発点として作り始めた。円形メーターの配置は、数学的な正確さ（半音距離の比例配置）よりも、**実機シールに忠実であること**を優先する

## 2. 想定ユーザー・利用環境

- 開発者本人（1名）。楽器演奏・五線譜の知識なし、移動ド唱法には慣れている
- **スマホのブラウザ**で使用（VT-12のような縦型・手持ちサイズのUI）
- VT-12実機と見比べながら開発・調整する

## 3. 必須機能（スコープ内）

| # | 機能 | 内容 |
|---|------|------|
| 1 | 基準音（音名）選択 | イロハニホヘトの自然音＋#（例：ヘ#）＝計12種類から選択 |
| 2 | オクターブ層選択 | 基準／ー1／ー2 の3段階（4段目の「＋」は実使用がないため廃止） |
| 3 | マイク入力によるリアルタイムピッチ検出 | ブラウザのマイク入力から歌声の基本周波数(f0)を検出 |
| 4 | 移動ド変換・表示 | 検出した音を、選択した基準音からの相対位置に変換し、実機VT-12のシール配置を再現した9分割の円形メーターで表示。「ミ短」「ラ短」の2区画は御詠歌の転調に対応する固定区画として常設 |
| 5 | 音程のズレ表示 | ジャストな音程からのズレ（セント単位）を円形メーターの光り方・色で表現 |
| 6 | メトロノーム | BPM設定（30〜90、デフォルト50）、開始/停止、拍子は常に2拍子固定。BPMの数値（表拍の間隔）は変えずに各表拍の間に裏拍を1つ挟むため、通常時は表拍2回＋裏拍2回＝計4回、倍速ボタンON時は表拍4回＋裏拍4回＝計8回鳴る。表拍のうち1・3打目（元の2拍子の頭）にアクセントが付き、裏拍はさらに控えめな音で表拍と区別する。画面に表示する丸（拍インジケーター）は表拍の数だけ（通常2個・倍速4個）とし、各ドットは自分の表拍のタイミングで1回だけ光る（アクセント＝黄色、非アクセント＝白）。裏拍は音のみで鳴らし、点滅はつけない |

## 4. スコープ外（あえて実装しない機能）

- 内蔵練習曲・トレーニングコンテンツ
- 録音・再生・レビュー機能
- 2声同時検出（コーラス機能）
- 教則本連携・ウォームアップモード

## 5. 基準音・オクターブ層の選択UI（2軸分離方式）

以前は「基準音×オクターブ」を1つの選択肢（例：ーーハ、ーハ、ハ、＋ハ…）としてまとめて考えていたが、7音×#の有無×オクターブ段階＝最大42通りとなり選びにくいため、**独立した選択UI**に分離する。

（一時期、音名とオクターブ層の間に「調（長調/短調）」選択を追加していたが、御詠歌は曲中で転調することがあり、曲全体を長調/短調のどちらかに固定するトグル方式は実態に合わないため撤去した。詳細は6-2参照）

### 5-1. 基準音（音名）選択：12種類
```
イ・イ#・ロ・ハ・ハ#・ニ・ニ#・ホ・ヘ・ヘ#・ト・ト#
```
（ホ-ヘ間、ロ-ハ間はもともと半音のため「ホ#」「ロ#」は存在しない＝ピアノの黒鍵5つに対応する数と一致）

### 5-2. オクターブ層選択：3段階
| 表記 | 意味 | 目安 |
|------|------|------|
| 基準 | 御詠歌の楽譜上の基準（記譜音） | 女性キーよりやや高め寄り |
| ー1 | 基準より1オクターブ下 | おおむね女性キー相当 |
| ー2 | 基準より2オクターブ下 | おおむね男性キー相当 |

「＋」（基準より1オクターブ上）は実際の声域で使用しないため廃止。

**プレビュー再生時の低域対策**：「ー2」を選択している状態でリング区画をタップしてプレビュー再生すると、iPhone等の内蔵スピーカーでは超低域が再生できずほぼ聞こえない問題があった。そのため、プレビュー再生（タップ時の音出し）に限り「ー2」のときだけ「ー1」相当の周波数で鳴らすよう変更した。ピッチ検出・判定に使う基準周波数（オクターブ層どおり「ー2」）自体は変更していない。実際に耳で確認し、歌う上での違和感がないことを確認済み。

### 5-3. 補足：男女ワンタッチ切り替え（検討中の追加案）
昔使っていた「コンダクター」という機械にあった、ボタン一つで基準音を1オクターブ下げて男性キー用に切り替える機能を、ショートカットボタンとして実装することも検討。実装が固まった段階で正式に採用可否を決める。

## 6. 円形メーター表示ロジック（実際のシールを再現）

### 6-1. 表示する9区画（実機同様12区画の枠に配置、固定・唯一の表示パターン）
実機VT-12は12個の固定ピッチ位置（半音ごと）を持つため、円形メーターも**12区画（30°ずつ）を土台**とし、そのうち9区画にラベルを配置する。残り3区画（実際に使わない半音の位置）は空白のまま残す。

```
反時計回り（上行方向）: ド → レ → ミ → ミ短 → ファ → ソ → ラ → ラ短 → シ → (ド)
```
円周上の配置（画像から再現、時計回り）：
```
ファ → (空白) → ソ → ラ短 → ラ → (空白) → シ → ド → (空白) → レ → ミ短 → ミ → (12時に戻る)
```
- 12時の位置：ミ（左）／ファ（右）が隣接
- 空白マスは**ド-レ間・ファ-ソ間・ラ-シ間**の3箇所（実機で使わない半音に相当）

### 6-2. ミ短・ラ短の扱い（転調対応、トグル方式の撤去経緯）
当初は「長調/短調」を切り替えるセレクタを実装し、短調を選ぶと「ミ」「ラ」の鳴る周波数がそれぞれレ#相当・ソ#相当に切り替わる仕様だった。しかし御詠歌は曲の途中で転調することがあり、**曲全体を長調/短調のどちらかに固定する**トグル方式は実態に合わないことが判明したため撤去した。

代わりに、旧「ミ#」「ラ#」の2区画を、転調時に使う音専用の**常設区画**として恒久的に置き換えた。ラベル（階名の呼び方）を変えるだけで、リング上の位置（実機シール配置）は変更していない。

| 旧ラベル | 旧semitone | 新ラベル | 新semitone | 備考 |
|------|------|------|------|------|
| ミ# | 5（ファと同じ） | ミ短 | 3 | レ#相当。実際に御詠歌で使うコンダクター実機で周波数を確認済み |
| ラ# | 10 | ラ短 | 8 | ソ#相当。同上 |

この変更により、9区画すべてが異なる周波数（semitone）を持つようになり、以前あった「ミ#とファの異名同音による同時ハイライト」は発生しなくなった。曲中で長調・短調どちらの音が必要になっても、セレクタの切り替えなしにいつでも該当区画をタップ・検出できる。

### 6-3. オクターブ違いの表示（実機検証で判明）
選択した基準音・オクターブ層から算出した「基準オクターブ」に対して、実際に検出された音が別のオクターブだった場合でも、移動ドの度数（階名）としては正しく同じ階名で表示されるべき。ただし、どのオクターブで鳴っているかが分かるよう、色を変えて区別する：

| 状態 | 表示色（例） |
|------|------|
| 基準オクターブと一致 | 赤 |
| 基準オクターブより下 | 黄 |
| 基準オクターブより上 | 青（実使用は少ない想定） |

計算式：検出周波数からセント差を算出し、最も近い階名区画を求める。オクターブ差は `round(12 × log2(検出Hz ÷ 基準ドHz) / 12)` 等で算出し、表示色に反映する。

## 7. 音域

- ピッチ検出自体は基準オクターブの前後1オクターブ程度（計3オクターブ弱）をカバーできるようにし、6-3のオクターブ判定ロジックで正しく色分けする
- 範囲外の周波数（ノイズ・倍音誤検出）は無視する

## 8. デザイン方針（VT-12シール踏襲・スマホ縦型）

```
┌───────────────────┐
│ 音名:[ハ▼] オクターブ:[基準▼]        │
│                             │
│        ミ  │  ファ           │
│    ミ短     (空白)   ソ       │  ← 実機同様12区画の枠
│    レ    ╭────╮   ラ短        │     （9区画にラベル、3区画は空白）
│  (空白)    │現在│   (空白)     │
│    ド    ╰────╯   ラ         │
│        シ                   │
│                             │
├───────────────────┤
│ ♪ BPM[ 50 ]       [ 倍速 ]   │
│      [ ● ○ ]（表拍のみ表示）│
│      [ 開始 / 停止 ]         │
└───────────────────┘
```
- 縦長（スマホ画面向き）の1画面完結レイアウト
- 音名・オクターブ層は横並びの2つの独立したセレクタ（調セレクタは撤去済み）
- 円周は実機同様12区画（30°ずつ）を土台とし、9区画にラベルを配置。残り3区画（ド-レ間・ファ-ソ間・ラ-シ間）は空白
- 現在検出中の音の区画を光らせる。オクターブ差は色で表現（6-3参照）
- 拍インジケーターのドットは表拍の数だけ表示（通常時2個・倍速時4個）。各ドットは自分の表拍のタイミングで1回だけ光り（アクセント＝黄色、非アクセント＝白）、裏拍は音のみで点滅はつけない（9技術方針参照）

## 9. 技術方針

- **形態**：ブラウザで動く単一Webアプリ（index.html / style.css / script.js）、サーバー不要
- **マイク入力**：`getUserMedia`
- **ピッチ検出**：Web Audio API の `AnalyserNode` ＋自己相関法（autocorrelation）
- **メトロノーム**：`AudioContext.currentTime` 基準の lookahead スケジューリング。拍子は常に2拍子固定。実際の御詠歌での使用範囲に合わせ、拍速（BPM＝表拍の間隔）は30〜90（デフォルト50）に制限。「倍速」ボタンで表拍の速さを2倍に切り替えられる（切り替え時は小節の頭にリセット）。さらに各表拍の間に裏拍を1つ挟んで鳴らす（裏拍機能。詳細は後述）
- **フレームワーク**：Vanilla JSで十分
- **スマホ対応**：viewportメタタグ、タッチ操作前提のUIサイズ、ポートレート固定推奨

**倍速機能**：「倍速」ボタンをONにすると、2拍子の表拍をそのまま2倍の速さで刻む。ONにすると表拍が1・2・3・4と4回打たれ、そのうち1・3打目（＝元の2拍子の頭）にアクセントが付く（2拍子を単純に倍速再生した自然な形）。倍速ON時はBPM表示・拍速スライダーの数値は変えず、内部の表拍間隔のみ半分にする。切り替え時は小節の頭にリセットする。

（以前は「2拍子／4拍子」を切り替える拍子ボタンも別途あったが、倍速ボタン1つで同じ表現ができ、ボタンが増えて分かりにくいため撤去した。拍子（beatsPerBar）は常に2で固定し、倍速のON/OFFのみで表拍の「タンタン」を通常速度で鳴らすか2倍速で鳴らすかを切り替える。）

**裏拍機能**：BPMの数値・意味（表拍の間隔）は変えずに、各表拍と表拍のちょうど中間に裏拍（オフビート）を1つ挟んで鳴らす。これにより実際に鳴る音の数は表拍数の2倍になり、通常時は表拍2回＋裏拍2回＝計4回（タン・ッ・タン・ッ）、倍速ON時は表拍4回＋裏拍4回＝計8回（タン・ッ・タン・ッ・タン・ッ・タン・ッ）鳴る。音色は3段階で区別する：強拍（1・3打目の表拍）は1500Hz・音量0.6、弱拍（それ以外の表拍）は1000Hz・音量0.35、裏拍は700Hz・音量0.2とし、裏拍は表拍よりさらに控えめで低い音にして耳で区別できるようにした。

**拍インジケーターのドット表示**：画面に表示する丸（ドット）の数は表拍の数だけとし、通常時2個・倍速時4個で固定する（裏拍のぶんはドットを増やさない）。速度（BPM・裏拍を含む鳴る回数）自体は変更せず、画面上の見た目だけをシンプルにした。ドットは表拍のみに対応し、各ドットは自分の表拍のタイミングで1回だけ光る。1・3個目（元の2拍子の頭）のアクセントは黄色、それ以外の非アクセントは白で点灯する。裏拍は音のみで鳴らし、点滅は一切つけない。

## 10. 音名対応（イロハ ⇔ 移動ド 変換ロジック）

```
イ = A (ラ)　ロ = B (シ)　ハ = C (ド)　ニ = D (レ)
ホ = E (ミ)　ヘ = F (ファ)　ト = G (ソ)
```
選んだ音名を「ド」として、検出周波数との半音差から、6章の円形メーターの区画を点灯させる。オクターブ層（基準/ー1/ー2）は、その「ド」の絶対的な高さ（何Hzか）を決定する役割。

22. **拍インジケーターの点滅を音に同期するよう修正**：ステップ21で裏拍を画面に表示しなくした結果、音（表拍・裏拍とも計4回/8回）と点滅（表拍のみ2回/4回）のタイミングが合わなくなっていた問題を修正。ドットの数は表拍のみ（通常2個・倍速4個）のまま変えず、各ドットが自分の表拍で明るく、直後の裏拍で控えめに光るようにし、点滅の回数・タイミングを実際に鳴る音と一致させた ✅（根拠：「音と点滅があっていません。音に合わせて点滅するように修正してください。」という指摘。9技術方針参照）→のちにステップ23でこの「音に完全同期」方針を撤回し、表拍のみ1回点灯に戻した
