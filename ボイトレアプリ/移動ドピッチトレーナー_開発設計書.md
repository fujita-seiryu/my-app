# 移動ドピッチトレーナー 開発設計書 (v2)

## 1. 背景・目的

- 御詠歌を行っており、**移動ド**（相対音感）の考え方には慣れている
- 一方で**楽器演奏の経験がなく、コード（和音記号）を見ても理解できない**
- Roland VT-12（ボーカル・トレーナー）の実機を所有・使用しているが、練習曲・録音再生・トレーニング機能などは不要で、機能過多に感じている
- **やりたいことはシンプルに1つだけ**：歌いながら自分の声のピッチを、移動ド（ドレミファソラシ）でリアルタイムに確認したい
- 基準音（キー、調）は、御詠歌や邦楽で馴染みのある**イロハニホヘト**（日本式音名）で選びたい
- メトロノームは欲しい（拍子の区別ありで）

## 2. 想定ユーザー・利用環境

- 開発者本人（1名）
- 楽器演奏・五線譜の知識なし。移動ド唱法には慣れている
- **スマホのブラウザ**で使うことを想定（VT-12のような縦型・手持ちサイズのUIレイアウト）
- VT-12の実機を所有しているため、操作感・見た目の参考として使える

## 3. 必須機能（スコープ内）

| # | 機能 | 内容 |
|---|------|------|
| 1 | 基準音（キー）選択 | イロハニホヘト（イ=A, ロ=B, ハ=C, ニ=D, ホ=E, ヘ=F, ト=G）＋半音（嬰イ/変ロ 等）から選択 |
| 2 | マイク入力によるリアルタイムピッチ検出 | ブラウザのマイク入力から歌声の基本周波数(f0)を検出 |
| 3 | 移動ド変換・表示 | 検出した音を、選択した基準音からの相対位置に変換し「ド・レ・ミ・ファ…」で大きく表示 |
| 4 | 音程のズレ表示 | ジャストな音程からのズレ（セント単位）を、**VT-12を踏襲した円形メーター**で視覚表示 |
| 5 | メトロノーム | BPM設定、開始/停止、**拍子（4拍子/3拍子など）に応じた強拍・弱拍の区別** |

## 4. スコープ外（あえて実装しない機能）

- 内蔵練習曲・トレーニングコンテンツ
- 録音・再生・レビュー機能
- 2声同時検出（コーラス機能）
- 教則本連携・ウォームアップモード

## 5. 音域

- **-ハ#（C#、1オクターブ下）～ +ハ（C、1オクターブ上）** を検出・表示対象とする
- 例：ハ＝C4(約261.6Hz) を基準とした場合、検出範囲はおよそ **C#3(約138.6Hz) ～ C5(約523.3Hz)** の1オクターブ強
- ノイズ・倍音誤検出を減らすため、この範囲外の周波数は無視する
- ※実際の声域に応じて範囲は微調整可能な設計にする

## 6. 半音表示ロジック（要確認事項あり）

### 6-1. 標準モード（デフォルト）
全12半音をそのまま表示：
```
ド → ド# → レ → レ# → ミ → ファ → ファ# → ソ → ソ# → ラ → ラ# → シ → ド(オクターブ上)
```
音楽理論上、ミ-ファ間とシ-ド間はもともと半音（隣接）のため、ミ#・シ#に相当する表示は出現しない。

### 6-2. ご指定の音階プリセット
ご提示いただいた「ド・レ・ミ・ミ#・ファ・ソ・ラ・ラ#・シ・ド」は、御詠歌特有の経過音・装飾音的な意味合いがあると思われるため、**選択式のプリセット音階**として実装する。

> ⚠️ **要確認**：「ミ#」は理論上ファと同じ高さになりますが、意図的に区別して表示したい場合はそのまま実装します（例：ファへ向かう途中の"上げ気味のミ"として、別の色・記号で表示するなど）。もし特に意図がなければ、この音は表示上ファと統合します。実装前に一度、実際の御詠歌でどの部分の音を指しているか（音源があれば）教えていただけると精度が上がります。

### 6-3. 長調・短調への対応
- 長調（メジャースケール）・短調（マイナースケール）の両方に対応
- 基準音（イロハ）選択に加えて「長調／短調」の切り替えUIを設ける
- 呂旋・律旋などの雅楽/声明系の旋法は、今回は正式対応せず「カスタム音階プリセット」の枠内で近似対応する（6-2参照）

## 7. デザイン方針（VT-12踏襲・スマホ縦型）

```
┌───────────────────┐
│  基準音: [ハ ▼]  長調/短調 [長▼]  │
│                             │
│        ╭─────╮             │
│      ╱         ╲           │  ← VT-12風 円形メーター
│     │     ミ     │          │     (中央に移動ド表示、
│      ╲   +8¢   ╱            │      円周でズレを視覚化)
│        ╰─────╯             │
│                             │
├───────────────────┤
│ ♪ BPM[ 92 ] 拍子[4/4▼]      │
│      [ ● 強拍 ○ ○ ○ ]       │  ← 拍子ごとの強拍/弱拍表示
│      [ 開始 / 停止 ]         │
└───────────────────┘
```
- 縦長（スマホ画面向き）の1画面完結レイアウト
- 円形メーター：中心に現在の移動ド階名、円周の光/色でピッチのズレ（フラット気味＝左、シャープ気味＝右など）を表現
- 操作は基準音・調・BPM・拍子の最小限のみ

## 8. 技術方針

- **形態**：ブラウザで動く単一Webアプリ（index.html / style.css / script.js）、サーバー不要
- **マイク入力**：`getUserMedia`
- **ピッチ検出**：Web Audio API の `AnalyserNode` ＋自己相関法（autocorrelation）
- **メトロノーム**：`AudioContext.currentTime` を基準にした lookahead スケジューリングで正確なタイミングを実現。拍子情報（何拍子か）を保持し、1拍目にアクセント音を鳴らす
- **フレームワーク**：Vanilla JSで十分（React等不要）
- **スマホ対応**：viewportメタタグ、タッチ操作前提のUIサイズ、画面回転はポートレート固定を推奨

## 9. 音名対応（イロハ ⇔ 移動ド 変換ロジック）

```
イ = A (ラ)　ロ = B (シ)　ハ = C (ド)　ニ = D (レ)
ホ = E (ミ)　ヘ = F (ファ)　ト = G (ソ)
```
選んだ基準音を「ド」として、検出周波数との半音差から移動ド階名を算出する。

## 10. Claude Codeでの実装ステップ（タスク分解）

1. プロジェクト雛形作成（index.html / style.css / script.js）、viewport設定
2. マイク入力取得・音量メーターで疎通確認
3. ピッチ検出アルゴリズム実装（自己相関法）→ コンソールに周波数を出力して確認
4. 基準音（イロハ）＋長調/短調 選択UI実装＋移動ド変換ロジック実装
5. 円形メーターUI実装（VT-12を参考に、中心階名表示＋周囲のズレ表示）
6. メトロノーム実装（lookaheadスケジューリング＋拍子ごとの強拍アクセント）
7. スマホ縦型レイアウトの全体スタイリング・調整
8. 実際に自分の声・実機VT-12と比較しながら動作確認、検出感度やUI反応速度を微調整

## 11. 未確定事項（開発着手前に確認したいこと）

- 円形メーターの具体的な配色・アニメーション方針（VT-12実機の写真等があれば近づけやすい）
- 拍子の種類はどこまで対応するか（4/4, 3/4のみで十分か、変拍子も必要か）
