# 移動ドピッチトレーナー 開発設計書 (v5)

## 1. 背景・目的

- 御詠歌を行っており、**移動ド**（相対音感）の考え方には慣れている
- 一方で**楽器演奏の経験がなく、コード（和音記号）を見ても理解できない**
- Roland VT-12（ボーカル・トレーナー）の実機を所有・使用しているが、練習曲・録音再生などの機能は不要
- VT-12使用時は、自作の**円形シール**（ド/レ/ミ/ミ#/ファ/ソ/ラ/ラ#/シの階名を記載）を本体の上に貼り、基準音が変わるたびに貼り替えて使っていた
- **これをデジタルで再現したい**：基準音を選ぶだけでシールの貼り替えなしに同じ表示が得られるようにする
- メトロノームも欲しい（拍子の強弱区別あり）

## 2. 想定ユーザー・利用環境

- 開発者本人（1名）。楽器演奏・五線譜の知識なし、移動ド唱法には慣れている
- **スマホのブラウザ**で使用（VT-12のような縦型・手持ちサイズのUI）
- VT-12実機と見比べながら開発・調整する

## 3. 必須機能（スコープ内）

| # | 機能 | 内容 |
|---|------|------|
| 1 | 基準音（音名）選択 | イロハニホヘトの自然音＋#（例：ヘ#）＝計12種類から選択 |
| 2 | オクターブ層選択 | 基準／ー1／ー2 の3段階（4段目の「＋」は実使用がないため廃止） |
| 3 | マイク入力によるリアルタイムピッチ検出 | ブラウザのマイク入力から歌声の基本周波数(f0)を検出 |
| 4 | 移動ド変換・表示 | 検出した音を、選択した基準音からの相対位置に変換し、周波数距離に比例した円形メーターで表示 |
| 5 | 音程のズレ表示 | ジャストな音程からのズレ（セント単位）を円形メーターの光り方・色で表現 |
| 6 | メトロノーム | BPM設定、開始/停止、拍子（4拍子など）に応じた強拍・弱拍の区別 |

## 4. スコープ外（あえて実装しない機能）

- 内蔵練習曲・トレーニングコンテンツ
- 録音・再生・レビュー機能
- 2声同時検出（コーラス機能）
- 教則本連携・ウォームアップモード

## 5. 基準音・オクターブ層の選択UI（2軸分離方式）

以前は「基準音×オクターブ」を1つの選択肢（例：ーーハ、ーハ、ハ、＋ハ…）としてまとめて考えていたが、7音×#の有無×オクターブ段階＝最大42通りとなり選びにくいため、**2つの独立した選択UI**に分離する。

### 5-1. 基準音（音名）選択：12種類
```
イ・イ#・ロ・ハ・ハ#・ニ・ニ#・ホ・ヘ・ヘ#・ト・ト#
```
（ホ-ヘ間、ロ-ハ間はもともと半音のため「ホ#」「ロ#」は存在しない＝ピアノの黒鍵5つに対応する数と一致）

### 5-2. オクターブ層選択：3段階
| 表記 | 意味 | 目安 |
|------|------|------|
| 基準 | 御詠歌の楽譜上の基準（記譜音） | 女性キーよりやや高め寄り |
| ー1 | 基準より1オクターブ下 | おおむね女性キー相当 |
| ー2 | 基準より2オクターブ下 | おおむね男性キー相当 |

「＋」（基準より1オクターブ上）は実際の声域で使用しないため廃止。

### 5-3. 補足：男女ワンタッチ切り替え（検討中の追加案）
昔使っていた「コンダクター」という機械にあった、ボタン一つで基準音を1オクターブ下げて男性キー用に切り替える機能を、ショートカットボタンとして実装することも検討。実装が固まった段階で正式に採用可否を決める。

## 6. 円形メーター表示ロジック（周波数距離に比例した配置）

### 6-1. 配置の考え方（実機シール踏襲から方針転換）
当初は実機VT-12のシールをそのまま模した9区画・等角度（40°ずつ）の固定配置としていたが、「唱えていても周波数の開きは感覚的に分かる」ため、**実際の半音距離どおりに角度を割り当てる**方式に戻した。

- 12半音 = 360° を等分し、**半音1つにつき30°**を割り当てる
- **ド（semitone 0）を12時**に固定し、そこから時計回りに半音が上がっていく
- 御詠歌の唱法で使わない半音（ド#/レ#/ファ#/ソ#相当＝1・3・6・8）には区画を置かず、そこは空白になる
- 結果として、隣り合う区画の間隔は半音1つ分なら30°、半音2つ分なら60°と、実際の音程差に応じて広さが変わる

### 6-2. 表示する8区画の配置（ドを12時とした時計回り）
| 階名 | semitone | 角度（12時=0） |
|------|----------|----------------|
| ド | 0 | 0°（12時） |
| レ | 2 | 60°（2時） |
| ミ | 4 | 120°（4時） |
| ミ#/ファ | 5 | 150°（5時） |
| ソ | 7 | 210°（7時） |
| ラ | 9 | 270°（9時） |
| ラ# | 10 | 300°（10時） |
| シ | 11 | 330°（11時） |

長調・短調の区別は設けず、常にこの1種類の階名パターンで表示する。

### 6-3. ミ#とファの扱い
**ミ#とファは異名同音（同じ周波数＝semitone 5）**のため、区画としては1つにまとめ、ラベルを「ミ#/ファ」と併記する（実機シールのように別区画には分けない）。

### 6-4. 区画の境目ちょうどの場合
半音距離に忠実に配置した結果、使っていない半音（1・3・6・8）はちょうど隣り合う2区画の中間にあたる。検出したピッチがその中間点ぴったりの場合は、両隣の区画を**同時にハイライト**する（ミ#/ファのケースと同じ仕組みで自然に処理される）。

### 6-5. オクターブ違いの表示（実機検証で判明）
選択した基準音・オクターブ層から算出した「基準オクターブ」に対して、実際に検出された音が別のオクターブだった場合でも、移動ドの度数（階名）としては正しく同じ階名で表示されるべき。ただし、どのオクターブで鳴っているかが分かるよう、色を変えて区別する：

| 状態 | 表示色（例） |
|------|------|
| 基準オクターブと一致 | 赤 |
| 基準オクターブより下 | 黄 |
| 基準オクターブより上 | 青（実使用は少ない想定） |

計算式：検出周波数からセント差を算出し、最も近い階名区画を求める。オクターブ差は `round(12 × log2(検出Hz ÷ 基準ドHz) / 12)` 等で算出し、表示色に反映する。

## 7. 音域

- ピッチ検出自体は基準オクターブの前後1オクターブ程度（計3オクターブ弱）をカバーできるようにし、6-5のオクターブ判定ロジックで正しく色分けする
- 範囲外の周波数（ノイズ・倍音誤検出）は無視する

## 8. デザイン方針（周波数距離比例・スマホ縦型）

```
┌───────────────────┐
│  音名: [ハ ▼]   オクターブ: [基準 ▼]  │
│                             │
│           ド                │
│    ミ#/ファ ╭────╮ レ        │  ← 半音=30°の周波数比例配置
│           │現在│              │
│      ラ#  ╰────╯   ミ       │
│           ソ                │
│      ラ                     │
│         シ                   │
├───────────────────┤
│ ♪ BPM[ 92 ] 拍子[4/4▼]      │
│      [ ● 強拍 ○ ○ ○ ]       │
│      [ 開始 / 停止 ]         │
└───────────────────┘
```
- 縦長（スマホ画面向き）の1画面完結レイアウト
- 音名とオクターブ層は横並びの2つの独立したセレクタ
- 円周の8区画はドを12時、半音=30°で配置（未使用の4半音は空白）
- 現在検出中の音の区画を光らせる。オクターブ差は色で表現（6-5参照）

## 9. 技術方針

- **形態**：ブラウザで動く単一Webアプリ（index.html / style.css / script.js）、サーバー不要
- **マイク入力**：`getUserMedia`
- **ピッチ検出**：Web Audio API の `AnalyserNode` ＋自己相関法（autocorrelation）
- **メトロノーム**：`AudioContext.currentTime` 基準の lookahead スケジューリング。拍子情報を保持し1拍目にアクセント音
- **フレームワーク**：Vanilla JSで十分
- **スマホ対応**：viewportメタタグ、タッチ操作前提のUIサイズ、ポートレート固定推奨

## 10. 音名対応（イロハ ⇔ 移動ド 変換ロジック）

```
イ = A (ラ)　ロ = B (シ)　ハ = C (ド)　ニ = D (レ)
ホ = E (ミ)　ヘ = F (ファ)　ト = G (ソ)
```
選んだ音名を「ド」として、検出周波数との半音差から、6章の円形メーターの区画を点灯させる。オクターブ層（基準/ー1/ー2）は、その「ド」の絶対的な高さ（何Hzか）を決定する役割。
